# Настройка Cursor для CHEIRO

Всё лежит в репозитории и подхватывается и локальным Cursor, и облачными агентами.

| Что | Где | Зачем |
|-----|-----|-------|
| Инструкции агентам | `AGENTS.md` | суть продукта, стек, ограничения, команды, git-процесс |
| Правила | `.cursor/rules/*.mdc` | постоянные (продукт, git, приватность) и по маске файлов (backend, RAG, интерфейсы, документация) |
| Скилы | `.cursor/skills/*/SKILL.md` | повторяемые процедуры: `add-rag-source`, `rag-eval`, `new-ui-screen`, `release-to-railway`, `sync-with-github`, `handoff-work`, `write-adr` |
| Субагенты | `.cursor/agents/*.md` | `rag-engineer`, `ui-reviewer`, `backend-reviewer`, `docs-writer`, `privacy-auditor` |
| Хуки | `.cursor/hooks.json`, `.cursor/hooks/` | форматирование после правок; блокировка force-push, пушей в `main` и коммитов с секретами |
| Правила Bugbot | `.cursor/BUGBOT.md` | ревью PR (`.mdc` на Bugbot не действуют) |
| Окружение облачных агентов | `.cursor/environment.json`, `scripts/cloud-agent-*.sh` | PostgreSQL + pgvector, Redis и зависимости для агентов без Docker |

## Как этим пользоваться

- Обычная работа: опишите задачу, агент следует `AGENTS.md` и правилам.
- Смена устройства: на текущем напишите «закончил работу локально», на следующем — «продолжи ветку <имя>» (скил `handoff-work`).
- Правка RAG: попросите использовать скил `rag-eval` или субагента `rag-engineer`; перед слиянием запускается `npm run eval`.
- Новый экран: скил `new-ui-screen`, затем ревью субагентом `ui-reviewer`.
- Перед PR с изменением приватности (фото, Telegram-авторизация, отчёты): `privacy-auditor`.
- Новый стек или тяжёлое решение: `write-adr`.

## Хуки

- `format-on-edit`: после правки файла агентом запускает ruff (Python) или prettier (frontend/admin). Если зависимости ещё не установлены, ничего не делает.
- `guard-shell`: перед командами `git` блокирует `push --force`, push в `main`/`master`, коммит файлов `.env*` (кроме `.env.example`) и коммит диффа, похожего на ключ или токен. Это страховка, а не замена внимательности.

Хуки написаны на Node и работают на Windows (там Cursor запускает их через PowerShell), macOS и Linux.

## Окружение облачных агентов

Облачный агент запускается в Linux-виртуалке без Docker. `scripts/cloud-agent-install.sh` ставит PostgreSQL с pgvector, Redis и зависимости (выполняется при сборке окружения), `scripts/cloud-agent-start.sh` поднимает сервисы при каждом старте. Благодаря этому агент выполняет `npm run check:integration` с настоящим pgvector.

Чтобы агент использовал этот файл, в Cursor Dashboard → Cloud Agents → Environments для окружения проекта выберите настройки из репозитория («Config as code», файл `.cursor/environment.json`) и запустите сборку. Пока окружение управляется из дашборда без сборки, агенты стартуют на образе по умолчанию без установленных зависимостей.

## Что намеренно не подключено

- MCP-серверы: пока не нужны. GitHub доступен агентам встроенными средствами. Railway MCP и Postgres MCP можно добавить в `.cursor/mcp.json`, когда появится потребность (токены хранить только в окружении).
- Storybook: каталог компонентов ведётся в `docs/design/`; отдельный инструмент добавим, если каталог станет неудобным.

## Обновление правил

Правила, скилы и агенты — часть кода: меняются через PR. Нашли повторяющуюся ошибку агента — добавьте правило или пункт в чек-лист скила, а не объясняйте заново в каждом чате.
