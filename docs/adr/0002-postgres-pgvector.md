# 0002. Одна БД: PostgreSQL + pgvector

- Статус: accepted
- Дата: 2026-11-17

## Контекст

Нужно хранить пользовательские задачи, метаданные книг и векторы фрагментов. Объём корпуса небольшой (3–5 книг, тысячи фрагментов).

## Решение

Один кластер PostgreSQL с расширением pgvector для всего. Поиск по косинусной близости (`<=>`), размерность вектора 1536 (`EMBEDDING_DIM`).

## Альтернативы

- Pinecone / Chroma отдельным сервисом: дополнительная инфраструктура и синхронизация данных.
- Хранение векторов в памяти: теряется при перезапуске, не масштабируется.

## Последствия

- Проще бэкапы и локальный запуск (`pgvector/pgvector:pg16`).
- На Railway нужен Postgres с pgvector (шаблон или образ `pgvector/pgvector`).
- Смена модели эмбеддингов с другой размерностью = миграция колонки и полная переиндексация всех книг.
- При росте корпуса добавится индекс HNSW/IVFFlat; сейчас точный поиск достаточен.
