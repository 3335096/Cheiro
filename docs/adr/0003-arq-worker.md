# 0003. Фоновые задачи на ARQ + Redis

- Статус: accepted
- Дата: 2026-11-17

## Контекст

Индексация книг (минуты) и анализ ладони (до 45 секунд) нельзя выполнять в HTTP-запросе. Нужен простой механизм фоновых задач на asyncio.

## Решение

ARQ поверх Redis. Один образ для `api` и `worker`, разные команды запуска. Redis также хранит временные данные задач (файлы и фото) с TTL.

## Альтернативы

- Celery: тяжелее, синхронная модель, больше конфигурации.
- FastAPI BackgroundTasks: нет повторов и изоляции, задачи теряются при перезапуске.

## Последствия

- Два процесса вместо одного (api и worker), оба в Railway.
- Данные больших задач не передаются аргументами: кладутся в Redis с TTL, воркер удаляет их после чтения.
- Горячей перезагрузки у воркера нет: после правок `docker compose restart worker`.
