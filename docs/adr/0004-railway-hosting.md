# 0004. Хостинг на Railway, локально Docker Compose

- Статус: accepted
- Дата: 2026-11-17

## Контекст

Нужно быстро выкатить первые тесты без отдельного DevOps. Работа ведётся локально на Windows, часть правок идёт из облачных агентов Cursor.

## Решение

Продакшен и тесты на Railway (сервисы: `api`, `worker`, `frontend`, `admin`, Postgres, Redis). Локально весь стек поднимается `docker compose`. Те же Docker-образы работают в обоих местах.

## Альтернативы

- Свой VPS + Portainer: больше контроля, но больше администрирования.
- Смешанный вариант: сложнее без пользы на этапе 1.

## Последствия

- Деплой и секреты в Railway выполняет владелец; репозиторий содержит Dockerfile и [runbook](../ops/railway.md).
- Конфигурация через переменные окружения (приложения читают `$PORT`, URL БД нормализуется под asyncpg).
- Переезд на другой хостинг не требует переписывания: образы те же.
