# Правила ревью для Bugbot — CHEIRO

Проект: Telegram Mini App для хиромантии с RAG (FastAPI, SQLAlchemy async, ARQ, PostgreSQL + pgvector, React + TypeScript). Над проектом работает один человек, поэтому ревью должно ловить ошибки, а не придираться к стилю (стиль проверяют ruff, prettier и CI).

## Критично (блокирует слияние)

- **Фото ладоней нигде не сохраняются:** запись изображения или base64 на диск, в БД, в логи, в сообщения об ошибках или в аналитику. В Redis допустим только короткий TTL с удалением после чтения.
- **Полный отчёт не должен возвращаться через API Mini App.** Только тизер; полный текст отправляет бот.
- **Авторизация:** пользовательские маршруты обязаны проверять подпись Telegram `initData` и отдавать данные только владельцу. Админские маршруты — только под `require_admin`.
- **Секреты:** токены, ключи, пароли в коде, тестах, `.env.example` и документации; вывод секретов в логи.
- Небезопасные значения по умолчанию, работающие вне `DEBUG`.

## Важно

- Блокирующие вызовы внутри `async`-кода (синхронные HTTP-клиенты, `embed_documents` вместо `aembed_documents`, тяжёлые вычисления).
- Схема БД: изменения моделей без миграции; смена `EMBEDDING_DIM` без плана переиндексации.
- RAG: правки чанкинга, промптов, `top_k`, моделей без результатов `npm run eval` в описании PR; ответы без ссылок на источники; медицинские или категоричные формулировки в промптах.
- Новая логика без теста; тесты, обращающиеся к реальным внешним API.
- Новая переменная окружения не добавлена в `Settings`, `.env.example` и `docs/ops/`.
- Изменение поведения без обновления `docs/` и `CHANGELOG.md`.
- Смена стека или добавление тяжёлой зависимости без ADR.

## Интерфейсы (frontend/admin)

- Отсутствуют состояния loading / error / empty; необработанные ошибки `fetch`.
- «Магические» цвета и размеры вместо дизайн-токенов; зона касания < 44 px; нет подписей у полей; нарушен контраст.
- Токены и ключи в `localStorage` в продакшен-коде.

## Не комментируй

- Стиль и форматирование, которые исправляют ruff и prettier.
- Тексты и названия на русском (это намеренно): код и коммиты английские, интерфейс и документация русские.
