# Передача работы между компьютером, телефоном и другим ноутбуком

GitHub — источник правды. Несохранённые файлы видны только агенту на том устройстве, где они лежат. Фразу завершения произносят в чате Cursor **на этом устройстве**. Облачный агент не видит диск Windows и не может залить оттуда файлы.

В `main` по этой фразе ничего не сливается. Публикуется ветка и pull request, чтобы другое устройство продолжило ту же работу.

## «Закончил работу»

Срабатывает на: «закончил работу», «закончил работу локально», «закончил работу с телефона», «залей на гитхаб», «можно с телефона», «можно с другого компьютера».

1. `git status`, `git diff` и `git diff --stat`. Нет изменений и ветка уже совпадает с upstream — ничего не коммить. Напиши имя ветки и ссылку на PR.
2. Не добавляй в коммит `.env`, `.env.*` (кроме `.env.example`), ключи, `*.pem`, `node_modules`, `.venv`, `__pycache__`. Если такой файл изменён, оставь его только на этом устройстве и скажи об этом.
3. Если текущая ветка `main` или `master`:
   - создай ветку по смыслу изменений: `feat/…`, `fix/…`, `docs/…` или `chore/…`;
   - если коммиты уже сделаны на локальном `main` и их нет в `origin/main`, сначала укажи на них новой веткой (`git branch <имя>`), запушь её, затем верни локальный `main` к `origin/main` (`git reset --hard origin/main`). Так можно только после успешного push новой ветки и только для локального `main`.
4. Закоммить оставшееся. Сообщение на английском, Conventional Commits, по смыслу diff. Пустой коммит не создавай. Несколько несвязанных тем — несколько коммитов.
5. `git push -u origin HEAD`. Без `--force`. В `main` не пушить.
6. Открой PR в `main` или обнови существующий по этой ветке. Повторный PR не создавай. В облаке используй инструмент pull request среды, не записывай через `gh`. Локально: `gh pr create` / `gh pr view --json url`, если `gh auth status` успешен.
7. В ответе: имя ветки, ссылка на PR, что вошло в коммит, и фраза для другого устройства: «продолжи ветку <имя>».

Проверки не блокируют публикацию: владелец переключается на другое устройство. Если `npm run check` в этой сессии уже падал или его не запускали — так и напиши. Красную проверку не скрывай и не отключай.

## «Продолжи работу»

Срабатывает на: «продолжи работу», «продолжи ветку <имя>», «начал работу», «продолжи с телефона», «продолжи на этом компьютере».

1. `git fetch origin`.
2. Ветка названа — переключись на неё (`git checkout <имя>` без `origin/`) и подтяни её (`git pull --rebase`), если нет незакоммиченных изменений.
3. Ветка не названа — возьми одну незакрытую ветку с работой, которой нет в `origin/main`: самую свежую среди `feat/`, `fix/`, `docs/`, `chore/`, `cursor/`. В первой фразе ответа назови её. Если таких веток нет, оставайся на свежем `main`.
4. Продолжай задачу на этой ветке. Не копируй её в новую и не начинай ту же работу заново от `main`.
5. Новая независимая задача — новая ветка от свежего `main`, не от чужой незаконченной ветки.

## «Слей в main»

Отдельная фраза, не часть передачи работы. Сливай только существующий PR и только когда проверки CI зелёные. Прямой push в `main` запрещён. Если среда не даёт слить PR, пришли ссылку и остановись — не обходи запрет пушем в `main`.
