# Оценка качества RAG

Цель: доказать, что изменение улучшило (или хотя бы не ухудшило) ответы.

1. **База:** убедись, что БД запущена, книги проиндексированы (`ready`), задан `OPENROUTER_API_KEY`.
2. **Замер «до»:** на чистой ветке без изменений `npm run eval`. Сохрани файл отчёта из `docs/eval/`.
3. **Одно изменение.** Внеси ровно одну правку (параметр чанкинга, промпт, `top_k`, модель). Если менялись чанкинг или эмбеддинги, переиндексируй источники.
4. **Замер «после»:** `npm run eval`. Для одного вопроса: `npm run eval -- --only <id>`.
5. **Сравни:** число пройденных проверок, источники в ответах, отдельно прочитай ответы вручную (автопроверки ловят только очевидное). Обрати внимание на галлюцинации, медицинские формулировки, язык ответа.
6. **Запиши результат** в `docs/rag/experiments.md`: что менялось, гипотеза, цифры, вывод, ссылка на отчёты.
7. Улучшение подтверждено → коммить правку и отчёты. Ухудшение или неясно → откати или проведи ещё один изолированный эксперимент.

Golden-набор пополняй реальными плохими ответами: каждая найденная ошибка должна стать тестом.
