# CHEIRO — инструкции для агентов

Этот файл читают все агенты Cursor (локальные и облачные). Подробные правила лежат в `.cursor/rules/`, процедуры в `.cursor/skills/`, специалисты в `.cursor/agents/`.

## Что за продукт

**CHEIRO** — Telegram Mini App (TMA) для анализа линий руки. Ядро продукта — **RAG на базе профессиональной литературы по хиромантии** (3–5 книг на старте, RU и EN, форматы EPUB и PDF). Точность и опора на источники важнее скорости разработки и количества функций.

Проект ведёт один человек без команды. Поэтому: простые решения, один стек на все этапы, всё запускается локально одной командой.

## Этапы

- **Этап 1 (сейчас):** RAG Foundation, один отчёт, бот и Mini App, полноценная админка. Без платежей.
- **Этап 2:** CloudPayments, интеграция с zhivo.crm, Astro как дополнение к отчёту, несколько типов отчётов.
- **Этап 3:** B2B API, нативные приложения, локализация ES/US.

Не реализуй этап 2–3 «заранее». Допустимы только точки расширения (env-переменные, адаптеры).

## Неизменный стек

Менять стек нельзя без записи ADR и явного согласия владельца.

| Слой | Технологии |
|------|------------|
| Backend | Python 3.12, FastAPI, SQLAlchemy 2 (async), ARQ + Redis |
| База | PostgreSQL + pgvector (и пользователи, и векторы в одной БД) |
| RAG | LangChain (разбор, чанкинг), OpenRouter (LLM и эмбеддинги) |
| Frontend (TMA) | React, TypeScript, Vite, Tailwind CSS + компоненты в духе shadcn/ui (Radix) |
| Админка | отдельное приложение `admin/` на том же стеке |
| Хостинг | Railway (сервисы: api, worker, frontend, admin, Postgres, Redis) |
| Локально | Docker Compose; команды через `npm run` (Windows, macOS, Linux) |

## Нерушимые ограничения

1. **Фото ладоней нигде не сохраняются:** ни на диск, ни в БД, ни в логи. Только в памяти и во временной очереди Redis с коротким TTL.
2. **Полный отчёт не отдаётся через API Mini App.** Только тизер. Полный текст идёт в бота (в этапе 2 это основа paywall).
3. **Секреты только в переменных окружения.** Никогда в коде, логах, `.env.example`, тестах, документации.
4. Каждый статус и результат доступны только владельцу (проверка Telegram `initData`).
5. Ответы RAG строятся на найденных фрагментах; нет данных — говорим об этом, не выдумываем.

## Команды

```bash
npm run setup              # один раз: venv, зависимости, .env
npm run dev                # весь стек в Docker Compose
npm run check              # те же проверки, что в CI (без БД)
npm run check:integration  # + тесты pgvector (нужен postgres: docker compose up -d postgres)
npm run fix                # автоисправление и форматирование
npm run eval               # прогон golden-набора RAG, отчёт в docs/eval/
npm run sync               # синхронизация с GitHub и облачными агентами
```

Перед завершением любой задачи запусти `npm run check`. Падающую проверку чини, а не отключай.

## Структура

```text
backend/    FastAPI, worker, RAG, тесты, evals
frontend/   Telegram Mini App
admin/      Админка (отдельное приложение)
docs/       Вся документация (см. docs/README.md)
scripts/    Кроссплатформенные скрипты (Node)
.cursor/    Правила, скилы, агенты, хуки, окружение облачных агентов
```

## Git и совместная работа

- `main` защищён: в него попадает только через PR с зелёным CI. Прямых коммитов в `main` нет.
- Ветки облачных агентов: `cursor/<описание>-<суффикс>`. Свои локальные: `feat/…`, `fix/…`, `docs/…`.
- Коммиты на английском, формат Conventional Commits: `feat(rag): …`, `fix(api): …`, `docs: …`, `chore: …`.
- Не делай force-push и не переписывай историю чужих веток. Не коммить `.env`.
- В начале работы: `npm run sync`. Перед работой с телефона владелец делает `git push`.
- Язык: документация, комментарии для людей и правила на русском; код, имена, коммиты, тексты ошибок API на английском. Текст интерфейса на русском (и английском для EN-локали).

## Документация — часть работы

Изменил поведение, архитектуру, RAG-параметры или интерфейс — обнови `docs/` и `CHANGELOG.md` в том же PR. Архитектурное решение оформляй как ADR (`docs/adr/`, скил `write-adr`).

## Облачные агенты

- В облачной VM нет Docker. Интеграционные тесты (pgvector) запускай через локальный PostgreSQL из окружения (`.cursor/environment.json`) или оставь CI.
- Всегда открывай PR по своей ветке и описывай проверку (шаблон PR подскажет).
